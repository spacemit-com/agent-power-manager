# Bibit Agent and Shared Multi-Agent Plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the built-in Bibit Agent for Skill, MCP, and Plugin while replacing Agent-specific Plugin Cloud/cache copies with one shared immutable multi-Agent artifact per Plugin version.

**Architecture:** Bibit is registered through the existing Agent profile/Adapter matrix: generic filesystem Skill, a dedicated `bianbu-agent` MCP Adapter, and a filesystem Plugin Adapter with no CLI activation. Cloud downloads one complete Plugin package per `PowerRef`; Plugin Resource builds both local marketplaces once and atomically publishes one shared cache artifact consumed by marketplace and filesystem Agents. Lifecycle and Transaction retain manifest-first behavior and schema v1 recovery, using logical Plugin names for every Agent.

**Tech Stack:** Go 1.24, Cobra CLI, standard-library filesystem/JSON/process APIs, `github.com/Masterminds/semver/v3`, table-driven tests, fake shell executables under `t.TempDir()`.

**Spec:** `ivory-tower/features/018-bibit-agent/spec.md`

## Global Constraints

- Agent ID is exactly `bibit`; executable is exactly `bianbu-agent`.
- Bibit root is `BIANBU_AGENT_HOME` when non-empty, otherwise `<effective HOME>/bianbu-agent`.
- Bibit Skill target is `skills/<name>`; Bibit and Hermes Plugin targets are `plugins/<name>`.
- All Plugin runtime names and Adapter selectors are logical `<name>`; versions remain in `PowerRef`, APM manifest, cache path, and native manifest.
- Cloud and Plugin Resource downloader APIs carry no Agent argument.
- Cache identity is exactly `plugins/<logical-name>/<version>` and contains one complete Plugin tree plus both generated marketplaces.
- Marketplace files are generated by APM during the first cache-miss build and are not Cloud resources.
- Bibit MCP command/output parsing stays in `bibit_mcp.go`; do not share a protocol implementation with Codex.
- Do not probe, execute, or modify a real `bianbu-agent`, real Agent home, or real `~/.apm`; all integration tests use `t.TempDir()` and fake executables.
- Do not add old Agent-aware cache, versioned selector, or old Plugin journal compatibility.
- Preserve the global lifecycle lock, manifest-first rules, schema v1 journal, fail-fast batch semantics, unlocked Search/List inspection, and offline Fix/Uninstall recovery boundaries.
- Cloud package completeness is owned by Cloud; APM retains only parsing required to generate marketplaces and local physical/cache/journal safety checks.
- Important public interfaces and lifecycle branches require concise Chinese comments.
- Do not add `docs/Changelog.md` until Tasks 1–11, whole-branch review, fixes, and fresh full verification pass.

## File Structure

- `internal/domain`: stable Agent identity and logical Plugin naming.
- `internal/adapter`: one Bibit MCP file, one Bibit Plugin file, common profile/Registry wiring, no empty Bibit Skill wrapper.
- `internal/cloud`: Agent-independent Plugin download and shared local fixture layout.
- `internal/pluginresource`: shared Artifact contract, atomic cache creation, two marketplace builders, generic filesystem staging.
- `internal/pluginartifact`: dependency-neutral read-only validation used by Plugin Resource and recovery.
- `internal/lifecycle`: manifest-first orchestration and marketplace/filesystem request mapping.
- `internal/transaction`: unchanged schema v1 envelope with logical target names and shared artifact recovery.
- `ivory-tower`: ADR/Feature/Project Overview/C4 truth; `BUILD.md` is the operator-facing example.
